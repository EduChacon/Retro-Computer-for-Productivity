Retro Computer 2.3.1 fixes authorization requests in the desktop assistant.

- MCP confirmation forms now show the requesting service, editable fields, **Allow once** and **Decline** inside the chat. Previously, these requests only offered Decline and incorrectly told users to continue in a separate terminal.
- Boolean, text, number, date and selection responses are validated in the main process and returned to the original pending request, so the same task can continue. Invalid responses keep the form open.
- Requests that require a service page show the full authorization URL and an **Open authorization** button. Navigation occurs only after the user clicks; the page opens in the isolated Retro Browser and the original agent connection receives the response.
- Existing Codex command/file approvals and Claude Code confirmations remain available in the chat. No approval or sandbox bypass is introduced.

Regression coverage includes both approval and decline, typed form data, validation errors, URL consent, unsafe URL rejection and the packaged Windows/macOS assistant flow. Tests use local provider fixtures and an intercepted authorization page, without signing into personal accounts or calling paid models.
