Retro Computer 2.4.0 adds two-way Google Calendar synchronization to Calendar. The existing internet-calendar subscriptions remain read-only.

- Open **Calendar › Google Calendar…**, sign in using the system browser, select a writable Google calendar and enable synchronization. Retro and Google events are combined by stable identifiers, and future creates, edits and deletions sync in both directions. An old read-only subscription to the same Google calendar is hidden to avoid duplicate presentation.
- Work offline, sync manually, pause or disconnect while keeping local events. Changes made on both sides produce an explicit choice between the Retro and Google versions. Incremental cursors, conditional Google writes and conditional local-file writes protect concurrent edits.
- Previous file versions and recovery copies preserve affected events before changes. Missing or invalid local calendar files do not delete Google events. Google fields outside the Retro editor are preserved, and guest invitations or notifications are not sent.
- Google sign-in uses the official desktop OAuth flow with PKCE, a loopback callback and system-vault storage. No password, refresh token or OAuth client configuration is exposed to the renderer or Retro MCP tools.

Google OAuth registration is required. Releases can include the application's desktop-client configuration through `GOOGLE_CALENDAR_CLIENT_JSON`; otherwise users can import a personal Desktop OAuth JSON file from the connection window. The Calendar API must be enabled and the account allowed by the project's audience/test-user settings. Linux requires an available password keyring. See [the setup and recovery guide](../google-calendar.md).

Automated coverage uses a local OAuth/calendar provider rather than a personal Google account. It exercises the UI in Portuguese, English and Spanish and in packaged Windows/macOS builds, including synchronization, conflicts, error recovery and disconnect. Real-account sign-in requires the OAuth setup described above.
