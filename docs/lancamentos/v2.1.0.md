Retro Computer 2.1.0 adds a Programming Laboratory and improves macOS packaging checks.

## New

- **Programming Laboratory**, in Start › Programs › Accessories, on Windows, macOS and Linux, including system mode. Edit and run single-file programs in **C, C++, C#, Python, Rust and Java**, with program input, output, compiler diagnostics and a Stop button.
- **Seven guided C lessons**, from Hello, world to pointers, with explanations and small challenges. The other languages include an editable example and a starter challenge.
- Source files stay ordinary files on drive C:, with previous versions. Opening a source file selects its language. The laboratory uses locally installed compilers or interpreters; **Set up language** checks the tool and explains how to install it. No compiler or paid service is bundled or required by Retro Computer itself.
- Exercises use the standard library only. Compilation has a 30-second limit, execution five seconds, and output is capped at 64 KiB. Input is supplied before execution. Programs have the user's permissions; these limits are not a sandbox. For interactive sessions or multi-file projects, use the Command Prompt and the same tools.

## macOS

- Explicit **ad hoc signing**, with the entitlements needed by Electron and its native components. This is local integrity signing, not Developer ID signing or notarization. macOS may still require System Settings › Privacy & Security › Open Anyway on first launch.
- Intel and Apple Silicon packages are built on runners of the matching architecture. The build verifies the signature and launches the packaged app, running the laboratory checks and keeping screenshots.
- Startup errors before the first window now show an error dialog.
- Installation instructions explain the **arm64 package for the Mac mini M4**, copying the app to Applications and checking a failed launch. The build test does not reproduce Gatekeeper quarantine on a newly downloaded file.
