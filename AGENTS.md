# Guia para agentes de IA — Retro Computer

Leia antes de mexer no código. Complementa o [README](README.md), o [docs/uso.md](docs/uso.md) (o uso no dia a dia) e o [docs/proposta.md](docs/proposta.md) (a arquitetura e as decisões).

## O que é

Um computador retrô para produtividade: um aplicativo Electron (Windows, macOS e Linux) com a área de trabalho no estilo do PC dos anos 90, o disco C: numa pasta comum do computador principal, os programas Craft instalados da versão oficial para navegador e o Claude Code no Prompt de comando. No Linux, ele também é o sistema do computador (o "modo sistema": a sessão "Retro Computer" da tela de entrada, com `RETRO_SISTEMA=1`), pensado para um notebook antigo ou um mini PC.

- **Dono:** EduChacon (repositório `EduChacon/Retro-Computer-for-Productivity`), código aberto, licença MIT.
- **Idioma:** o código, os comentários, os nomes, os commits e a documentação em português do Brasil, com acentos. A interface fala português, inglês e espanhol (veja "Idiomas"). A página do GitHub é em inglês (`README.md`, com `README.pt-BR.md` e `README.es.md`), assim como as notas dos lançamentos (`docs/lancamentos/`).

## Regras que não se negociam

1. **Nada da Microsoft nem da Apple.** Nenhum ícone, fonte, som, logotipo ou papel de parede deles, nem "só por enquanto". Os ícones vêm do SerenityOS (BSD-2-Clause) ou são desenhos próprios (`ferramentas/icones.py`); as fontes vêm do SerenityOS (`ferramentas/fontes.sh`); os sons são sintetizados (`src/sistema/js/sons.js`). Todo recurso novo de terceiros entra em [ATRIBUICOES.md](ATRIBUICOES.md) no mesmo commit.
2. **Os Craft não entram no repositório nem no instalador.** Eles são baixados do lançamento oficial na hora da instalação (`src/principal/programas.js`), sem modificação.
3. **Nada se perde.** O disco nunca apaga sem pedido do usuário: excluir vai para a Lixeira, gravar por cima guarda a versão anterior. Um caminho do disco nunca sai da pasta dele (`Disco.real`).
4. **Não apague arquivos do repositório.** O que precisar sair vai para `_to_delete/` (ignorado pelo Git), e a exclusão fica a critério do dono.
5. **A chave de API não aparece** na área de trabalho, no disco, nos registros nem nos commits; ela só vai para o terminal (`ANTHROPIC_API_KEY`).
6. **Antes de recurso novo grande, pergunte.** "Tem como…?" às vezes é só uma pergunta.
7. **Todo texto da interface passa por `tr()`**, com a tradução em `src/sistema/idiomas/en.json` e `es.json`. O `npm test` falha se faltar uma.
8. **Uma atualização nunca volta atrás nem perde nada**: só instala versão maior que a instalada (`instalar(…, { atualizar: true })`) e não troca o que veio de um `.zip`.

## Rodar, testar e compilar

```
npm install                 # instala e compila o node-pty para o Electron
npm start                   # abre o Retro Computer
npm test                    # os testes (node:test)
node ferramentas/textos.js  # as traduções que faltam ou sobram
xvfb-run -a node testes/capturas.mjs SAIDA geral    # capturas (Linux sem tela)
npx electron-builder --linux dir --publish never     # empacotar sem instalar
```

Variáveis úteis: `RETRO_DADOS` (pasta das configurações), `RETRO_DISCO` (pasta do disco C:), `RETRO_JANELA=1` (sem tela cheia), `RETRO_RAPIDO=1` (sem a abertura), `RETRO_IDIOMA=en` ou `es` (o idioma, por cima da configuração), `RETRO_SISTEMA=1` (o modo sistema), `RETRO_ZIP` (no roteiro de capturas: instala pacotes `.zip` antes), `RETRO_FALSA_VERSAO=9.9.9` (no roteiro de capturas: finge que a busca achou essa versão), `RETRO_SEM_BOAS_VINDAS=1` (sem a Ajuda e o balão da primeira vez), `RETRO_EXECUTAVEL` (testa o aplicativo empacotado), `RETRO_SEM_RELANCAR=1` (a troca de usuário, o logoff e a troca de idioma só fecham o aplicativo, com o código 75, sem abri-lo de novo: o roteiro `perfis` o abre), `RETRO_ESQUEMA=noite` (no roteiro de capturas: qualquer roteiro num esquema de cores do PC clássico, `esquemas.js`), `RETRO_TEMA=mac` (no roteiro de capturas: qualquer roteiro no tema Mac clássico; os seletores `#iniciar` e `.janela.ativa .menubar` passam a ser o logotipo e os menus da barra no alto, `SELETORES_MAC`).

As ferramentas do sistema têm versões de mentira, para os testes e as capturas sem o aparelho: `RETRO_ENERGIA_FALSA=1` (desligar, reiniciar e suspender só são anotados, assim como o `xset` e a tampa das Opções de energia, cuja senha de teste é "certa": use-a sempre com `RETRO_SISTEMA=1` fora de um computador dedicado), `RETRO_DATAHORA_FALSA=1` (o `timedatectl`; a senha de teste é "certa"), `RETRO_ACESSIBILIDADE_FALSA=1` (o `xkbset`), `RETRO_ANTIVIRUS_FALSO=1` (um verificador que acha o arquivo de teste EICAR), `RETRO_WINE_FALSO=1` (o WINE só anota o que abriria), `RETRO_BANDEJA_FALSA=1` (volume, brilho, bateria e Wi-Fi), `RETRO_LOJA_FALSA=1` (o Flathub de verdade, o flatpak de mentira; com `winget`, a loja do Windows, com os manifestos de verdade e o winget de mentira; com `brew`, a do Mac, com a lista do Homebrew de verdade e o brew de mentira), `RETRO_UNIDADES_FALSAS=<pasta>` (um pendrive; no programa Discos, ele e um segundo, com o Linux gravado: formatar só confere a senha de teste, "certa", e gravar copia a imagem para um arquivo temporário), `RETRO_COMPUTADOR_FALSO=<pasta>` (as pastas do computador principal: `desktop`, `documents`, `downloads`… dentro dela), `RETRO_IMPRESSORAS_FALSAS=1`, `RETRO_BLUETOOTH_FALSO=1`, `RETRO_ATUALIZACOES_FALSAS=1` (a senha de teste é "certa"), `RETRO_JANELAS_FALSAS=1` (dois programas do Linux abertos), `RETRO_TELA_FALSA=1` (a resolução de um notebook de 1440 × 900; ## Idiomas

- Na área de trabalho: `import { tr } from '../idioma.js'` e `tr('Não foi possível abrir {nome}.', { nome })`. Nunca monte frases juntando pedaços traduzidos: a ordem das palavras muda de um idioma para outro. Em tabelas de módulo (lidas antes do idioma carregar), use `marcar('…')` e traduza na hora de mostrar com `tr(item.rotulo)`.
- No processo principal: `const { tr } = require('./idioma')`.
- Depois de mudar textos, rode `node ferramentas/textos.js`, acrescente as traduções que faltam em `en.json` e `es.json` (na ordem das chaves, `--chaves` lista todas) e tire as que sobram. Os `&` marcam a letra sublinhada dos menus: escolha letras que não se repitam no mesmo menu.
- Nomes de referência: Iniciar = Start / Inicio; Meu computador = Computer / Mi computadora; Meus documentos = Documents / Mis documentos; Lixeira = Trash / Papelera; Prompt de comando = Command Prompt / Línea de comandos; Bloco de notas = Notepad / Bloc de notas; Foco = Focus / Enfoque; computador principal = main computer / computadora principal.
- A Ajuda (`js/apps/ajuda.js`) e as descrições do catálogo (`catalogo/programas.json`) têm o texto de cada idioma no próprio lugar.

## Publicar uma versão

1. Suba a versão no `package.json` (e no `package-lock.json`) e na linha "Version" dos três READMEs.
2. Escreva as notas em inglês em `docs/lancamentos/vX.Y.Z.md`.
3. Teste (`npm test`, as capturas nos três idiomas), faça o commit e o push na branch de trabalho, e espere o fluxo "Compilar" passar nos quatro sistemas.
4. Leve o commit para a `main` (`git push origin <commit>:main`). O fluxo "Publicar" vê que a versão do `package.json` ainda não tem lançamento, compila os instaladores (Windows, macOS, Linux PC e ARM64) e cria o lançamento `vX.Y.Z`, com a etiqueta. Sem versão nova, ele não faz nada. Não é preciso enviar etiquetas (nas sessões na nuvem, o envio de etiquetas é recusado).
5. O Retro Computer instalado avisa os usuários da versão nova (consulta o último lançamento uma vez por dia).

## Como editar

- Prefira a ferramenta de edição ou scripts de troca de texto que conferem se acharam o trecho. Não use `t.replace(a, b)` com texto em JavaScript (os padrões `$&` e `$'` corrompem o arquivo); use a função.
- Comentários curtos em português, explicando o porquê.
- A área de trabalho não tem empacotador: são módulos ES carregados direto (`src/sistema/js`). O processo principal é CommonJS.
- Um programa novo da área de trabalho é um módulo em `js/apps/` que chama `registrarApp(id, { nome, icone, abrir })`. Em `js/inicio.js`, ele entra com `registrarPreguicoso` (só carrega quando abre, ou com o computador parado depois da abertura); só vai num `import` direto quando faz algo ao carregar (ouve o processo principal, tem relógio próprio) ou abre arquivos pelo tipo (`tipos`). Para entrar no Iniciar, ele vai em `itensProgramas` (`js/barra.js`); para a Ajuda, um tópico em `js/apps/ajuda.js`, nos três idiomas.
- A ponte (`tratar` em `main.js`) só atende o quadro principal da área de trabalho (`sistema://retro`): os programas Craft falam por mensagens com `craft.js`, e as páginas do Navegador, com o `navegador-preload.js`.
- O `userChrome.css` do Firefox (`firefox.js`) não pode ter `@namespace`: com ele, o Firefox 158 ignora o arquivo inteiro. Os nomes das peças da interface mudam de uma versão para outra; para conferir, abra o `browser/omni.ja` do Firefox (é um zip) e procure no `chrome/browser/skin/classic/browser/`. A largura das abas vai pelas variáveis do Firefox (`--tab-min-width`, `--tab-max-width`), nunca por um `max-width` na aba: ao fechar, ele encolhe a aba até 0,1 ponto e só então a tira, e um `max-width` com `!important` deixava a aba fechada como um espaço vazio. O E-mail e os sites instalados como programas abrem numa janela nova do Firefox (`novaJanela`, o `--new-window`) quando ele é o navegador padrão (`usaFirefox`): o Google recusa o login no navegador embutido. O visual imita o do Navegador: a barra de menus, as abas, o campo do endereço afundado e os ícones de 16 pontos da área de trabalho (os de `ICONES`, copiados para a pasta `chrome/` do perfil a cada abertura; um ícone novo no CSS entra na lista, e o teste confere). O tamanho é o `layout.css.devPixelsPerPx` = o tamanho dos pixels exato (`textoEscala`), lido do `devicePixelRatio` da área de trabalho, que já leva o zoom dela: não o multiplique pelo `zoomInterface` (até a 2.0.1 era assim, e o Firefox ficava com o dobro do tamanho).
- As teclas de função do portátil no modo sistema (`teclas-linux.js`): o Chromium não pega o brilho, a luz do teclado, o F3, o F4 e o botão de ligar com um programa do Linux na frente (o `globalShortcut` não os conhece), e a luz do teclado ele nem reconhece. Por isso o Retro Computer põe um atalho para cada tecla (`TECLAS`) no bloco `<keyboard>` da cópia do rc.xml (`trocarTeclas`, pelo `editarRc` de `janelas-linux.js`, que serializa com as margens), e o atalho escreve o nome da ação na fila (um FIFO em `$XDG_RUNTIME_DIR/retro-computer/teclas`, aberto com `O_RDWR | O_NONBLOCK` num `net.Socket`, numa pasta 0700 do usuário; só as ações de `ACOES` valem). Uma tecla nova entra em `TECLAS`, com a ação tratada no `sistema:tecla` da área de trabalho. Com o atalho do botão de ligar no lugar, a trava "block" do logind (`TravaDoBotao`, `--what=handle-power-key`) não deixa o computador desligar na hora; sem o atalho, a trava não é pedida. A mídia passa pelo mesmo caminho (assim ela não depende de quem está na frente) e vai para o tocador do MPRIS que está tocando (`escolherTocador`; o Firefox e o próprio Retro Computer, o `org.mpris.MediaPlayer2.chromium.*`, aparecem nele). A luz do teclado é o `*::kbd_backlight` de `/sys/class/leds` (`LuzTeclado` em `bandeja.js`), mudada pelo `SetBrightness` do logind como o brilho da tela. Cuidado nos testes: um `pkill -f` com um texto que aparece no próprio comando do roteiro mata o roteiro.

Por isso a sessão (`sessao.sh`) e o `main.js` põem `XCURSOR_THEME=Adwaita` (o Adwaita vem com o GTK). Para comparar dois ponteiros sob o Xvfb, leia a imagem pelo XFixes (`XFixesGetCursorImage`) com o ponteiro sobre cada janela.

As ações de administrador passam por `comoAdmin` (`sistema-linux.js`), com a senha pedida pela caixa do Retro Computer (`js/admin.js`).

Confira com o roteiro `duasTelas`.

- Os vários usuários (`perfis.js`): cada perfil tem a própria pasta de dados (o `userData`, trocado logo no começo do `main.js`, antes de ler o idioma), e o principal fica com a de sempre. O que é de todos (os programas instalados, o WINE) usa `BASE_DADOS`; o resto, `app.getPath('userData')`. A trava de uma instância só fica na pasta principal. Trocar de usuário, fazer logoff e trocar de idioma passam por `reabrirApp()`: com a "próxima abertura" (`abertura.json`, que vale uma vez e por dois minutos) e o `app.relaunch()`; na sessão do Linux (`--sistema`), o código 75, que o `sessao.sh` entende como "abrir de novo" (o `relaunch` abriria fora da sessão).
- A segurança (a auditoria da 1.0, com os testes em `testes/auditoria.test.js`): os arquivos do disco em `sistema://retro/disco/` e `/miniatura/` saem com a CSP `sandbox` (`soConteudo`), para um .svg ou um .html nunca rodar com a origem da área de trabalho; a janela só navega para `sistema://retro/index.html` e nenhum quadro abre `sistema://` (`will-frame-navigate`); `/papel/` só serve as cópias dos papéis de parede, pelo nome do resumo (`papel.js`); `programa://<id>` só serve um programa instalado (o Chromium entrega `..` como nome); o download dos Craft confere o SHA-256 publicado pelo GitHub; um Craft lê a área de transferência só com a permissão do usuário (`permissoesProgramas`); `Disco.real` segue os links até o fim; os arquivos que o administrador copia para o sistema saem de `temporario()` (`sistema-linux.js`). Ao mexer nesses lugares, rode o roteiro `auditoria`.
- As pastas do computador principal (`PastasDoComputador` em `unidades.js`, os ids `pc:…` nas rotas dos pendrives) só existem fora do modo sistema e só para a área de trabalho; para os outros usuários, começam escondidas (`foraVisivel` em `main.js`). A pasta do disco C: nunca aparece nelas nem vai ou volta por elas (trazer de dentro dela viraria mover no disco). O que o computador principal manda (a linha de comando da segunda abertura e o `open-file` do Mac) só é copiado para Recebidos, depois de a área de trabalho avisar que está pronta (`computador:pronto`); nada abre sozinho. A cópia levada para fora leva a marca de "baixado da internet" (`copiarMarcas`).
- Arrastar e soltar: os arquivos e as pastas do disco saem pelo arrastar do sistema (`comecarArrastoNativo` em `arquivos.js`, `webContents.startDrag` em `main.js`), que também solta fora do Retro Computer e só copia; soltos de volta numa pasta daqui, chegam como arquivos de fora, e `relsDoArrasto` reconhece que são os do disco (e move). No Linux sem um idioma UTF-8 o Chromium perde os acentos dos caminhos, e fica o arrastar de dentro (`arrastoSistema` em `config:obter`). O Playwright só imita o arrastar do navegador: o roteiro `arrastar` o liga (`window.__retro.arrastoSimulado`), e o `arrastarReal` confere o do sistema, com uma janela de mentira ao lado que recebe o arquivo. Todo lugar que aceita uma soltura aceita o `dragenter` e o `dragover` (o Chromium responde ao sistema pelo `dragenter` ao trocar de elemento, e um `dragenter` recusado logo antes de soltar faz o Windows e o X desistirem), e a marca de "por cima" não muda o tamanho de nada. Confira com o roteiro `arrastarReal`, não só com o `arrastar`.
- O Mac Plus (o pacote `pcejs-macplus`, o PCE.js, GPL-2.0) vai sem modificação e no mesmo esquema do DOS: o quadro isolado em `mac://emulador` (`macintosh.js` e `src/mac/`), as mensagens com a origem conferida e a CSP própria, sem `unsafe-eval`. Nada da Apple entra no repositório, no instalador nem nos testes: a ROM, o System e os jogos são do usuário (o roteiro `mac` usa uma ROM de teste feita na hora, que só pinta a tela). Os discos vão para a memória do emulador sem cópia e com `type = "image"` (o PCE grava direto neles; com o `auto`, os disquetes ficariam numa cópia que só volta ao desligar), e a janela pede só os que mudaram (pela hora do arquivo na memória). A tecla de escape do PCE é a ScrollLock, e a página não deixa passar a ScrollLock, a Pause (que desligaria o emulador), o Ctrl+` e a PrintScreen. Nos textos dentro de `` `…` `` (a Ajuda), o caminho vai com a barra dobrada (`C:\\Mac`): com uma só, ela some.
- O processo de trabalho (`trabalho.js`, o `utilityProcess` do Electron) é o lugar do que lê arquivos de fora e pode travar ou estourar a memória: as ferramentas de PDF, o OCR e o texto para a busca. Ele não tem a ponte nem o disco: recebe bytes e devolve bytes ou texto, e quem lê e grava o disco C: (com os limites de tamanho) é o processo principal. Uma tarefa nova entra em `TAREFAS` (`trabalho-processo.js`), com os erros por código (`err.codigo`), que o processo principal traduz. Três cuidados: o pdf-lib lê o JPEG por `bytes.buffer`, sem o deslocamento da vista, e os bytes das mensagens podem ser uma vista no meio de um buffer maior (`proprio` em `pdf-ops.js`); o tesseract.js 7.0.0, no Node, carrega sempre o núcleo completo (`tesseract-core*.js`, não os `-lstm`), por isso o instalador leva esses; e o pdf.js do Node é o da versão legacy, com o worker compactado (`GlobalWorkerOptions.workerSrc`), os dois únicos arquivos dela no instalador. Confira cada mudança nisso com o aplicativo empacotado (`npx electron-builder --linux dir` e `RETRO_EXECUTAVEL`): o `app.asar` muda o caminho dos módulos.
- Com uma caixa modal aberta, o foco fica nela (o `focusin` em `janelas.js`): um programa que pega o foco de volta com um `setTimeout` depois de outra caixa fechar não leva as teclas da caixa seguinte.
- O observador do disco (`observar.js`): no Linux, o `fs.watch` recursivo do Node vigia cada arquivo pelo inotify dele e, depois de uma gravação segura (o temporário renomeado por cima, como o `Disco.gravar` faz), perde as gravações seguintes feitas no lugar por outro programa. Por isso, no Linux, há uma vigia por pasta (as novas e as renomeadas entram sozinhas; as versões guardadas e o que há dentro da Lixeira ficam de fora); no Windows e no Mac, o recursivo do sistema. `testes/observar.test.js` reproduz o caso.
- A área de trabalho não muda `pastas` nas configurações (o `config:definir` recusa), com duas exceções: os nomes da Agenda (`pastas.agenda`) e da pasta das notas (`pastas.notas`), aceitos só uma vez e só com um nome válido, para trocar de idioma não criar outros.
- Reabrir ao ligar (`reabrir.js`): um programa que mostra algo diz o que reabrir por `j.reabrir = () => ({ arquivo })` (ou `null` para não voltar); sem isso, ele abre como pelo Iniciar. O que começa algo ao abrir (um terminal, um emulador) fica na lista `FORA`. Desligar, reiniciar e o logoff chamam `prepararParaSair()` antes de fechar as janelas.
- O Receber do celular (`receber.js`) é o único servidor que o Retro Computer abre na rede: só com a janela aberta, só no endereço da rede local, com o código de uso único, a aprovação de cada aparelho e os limites (`testes/receber.test.js`). Ele não serve nada do disco; um recurso novo nele não pode ler arquivos nem aceitar outros endereços.
- O DOSBox do Linux (`DosNativo` em `dos.js`): no Linux, com o DOSBox do sistema (`dosbox-staging`, `dosbox-x` ou `dosbox`) ou o do Flathub instalado, o DOS roda nele, numa cópia da pasta (em `os.tmpdir()`, ou na pasta do programa do Flathub, `~/.var/app/<id>/`, a única que ele enxerga), e o que mudou volta pelo `Dos.guardar` (a versão anterior e a Lixeira), ao fechar e a cada dois minutos. O `dosbox.conf` monta a cópia e roda o `config -securemode` logo depois: sem ele, um .bat montaria outras pastas do computador e apagaria arquivos sem passar pela Lixeira. A cópia só sai depois de guardada. Confira com o roteiro `dosNativo` (com o `dosbox` do apt) e com `testes/dos.test.js` (um DOSBox de mentira).
- O DOS (o pacote `emulators`, GPL-2.0) vai sem modificação. Ele avalia o próprio código com `eval`, que a área de trabalho não permite: por isso roda em `dos://emulador` (um quadro com `sandbox`, sem a ponte, com a CSP própria de `dos.js` e sem internet) e só conversa por mensagens, com a origem conferida dos dois lados. Não afrouxe a CSP do `index.html` por causa dele.
- O tema Mac clássico (`tema.js`) é a classe "tema-mac" na raiz e o estilo de `tema-mac.css`, sempre com `html.tema-mac` na frente; a regra geral de um elemento (os botões, os campos) vai com `:where(html.tema-mac)`, para os botões planos dos programas ficarem como são. Nada da Apple, como em todo o projeto: os controles são desenhados em `ferramentas/controles-mac.js` (que grava o bloco "controles" do CSS) e os ícones em `ferramentas/icones-mac.py` (o ícone que falta fica o do PC; um ícone novo entra lá, nos dois tamanhos; o globo usa os continentes de verdade, da máscara `MAPA_TERRA`, feita do Natural Earth). A luz e a sombra de um desenho vão um ponto para dentro do contorno, nunca por cima dele (`fechar_contorno` deixa a borda de fora preta no fim, e `testes/tema.test.js` confere); o sinal de dentro de um botão ou de um balão fica no meio dele, com a largura par num círculo de largura par. Mudar o tema por onde for (o Painel, o Claude) troca o fundo de sempre de um pelo do outro (`fundoParaTema`, no ouvinte de `config` em `inicio.js`). Algo que fica na barra de tarefas precisa de um lugar no tema Mac (a barra de menus no alto, `barra-mac.js`, ou a Faixa de controle), e o que abre a partir de uma barra abre para baixo quando ela está no alto. Confira com o roteiro `temaMac` e com `RETRO_TEMA=mac` nos outros roteiros.
- Os Discos (`discos.js`) só mexem nos discos de USB e nos cartões removíveis (no Linux, `rm` ou `tran` usb, nunca o interno com "hotplug"; no Windows, o `BusType` USB ou SD; no Mac, o externo ou de mídia removível) e nunca no que tem montado algo do sistema ou um dos `protegidos` (o disco C:, os dados, o programa: o modo portátil). As ações de administrador ficam nos roteiros de `ps/`, que vão para uma pasta temporária antes de rodar (o PowerShell e o sh não leem o .asar). No Windows, o `Start-Process -Verb RunAs` pede a confirmação do UAC e devolve 1223 quando ela é cancelada; o resultado vem num .json. Na gravação, o primeiro MiB (a tabela de partições) é zerado antes e gravado por último, depois de conferido o resto, para o sistema não montar o pendrive no meio. Os testes (`testes/discos.test.js`) rodam o `gravar.sh` e o `gravar.ps1` de verdade num arquivo no lugar do disco (o `-ArquivoTeste` e o modo `teste`), este com o PowerShell da máquina (`pwsh`, ou o de `RETRO_PWSH`).
- As cores do `estilo.css` são variáveis (`--face`, `--texto`, `--janela` para o fundo dos campos e das listas, `--texto-meio`, `--texto-fraco`, `--destaque` para as letras em destaque, `--alerta`, `--sucesso`), que os esquemas de cores trocam (`esquemas.js`). Uma cor nova da interface usa uma delas, não um `#fff` ou um `#000` fixo, senão ela não acompanha os esquemas escuros; ficam fixas só as do "papel" (os documentos na visualização, as páginas digitalizadas, as cartas, as notas) e as telas pretas. Uma variável nova entra no `:root`, em cada esquema e em `testes/esquemas.test.js`, que confere. Confira com `RETRO_ESQUEMA=noite` nos roteiros.
- A troca do esquema à noite (`esquemaNoite` nas configurações): o esquema desta hora sai de `esquemaDaHora` (`esquemas.js`), e quem o aplica é o `acertarEsquema` de `inicio.js` (ao abrir, a cada minuto e a cada mudança da configuração), que troca o fundo de sempre de um esquema pelo do outro. O pôr e o nascer do sol vêm de `sol.js`, pela cidade de referência do fuso horário do computador (`Intl`), sem pedir a localização; sem a cidade (o fuso UTC, por exemplo), valem as horas. A conta usa o dia solar mais perto do instante, para não depender do fuso de quem a roda; `testes/sol.test.js` a confere com a planilha do NOAA. A luz noturna usa o mesmo `quando: 'sol'`.
- As áreas de trabalho (`janelas.js`): cada janela tem `area`, e só as da área de agora ficam à vista (`daAreaAtual`). Uma lista de janelas que o usuário vê (a barra, o Alt+Tab, o menu dos programas do tema Mac, o "minimizar tudo", o "em cascata") filtra por `daAreaAtual`; uma janela que vem para a frente (`focar`) leva para a área dela.
- O painel de emojis põe o texto pelo `insertText` do processo principal (`sistema:inserirTexto`: até 32 caracteres, sem os de controle) ou, na página do Navegador, pelo `insertText` do webview. Os desenhos são os da fonte Noto Color Emoji (as fatias COLRv1 do Google Fonts: as do pacote @fontsource são OpenType-SVG, que o Chromium não desenha), a família "Retro Emoji", que vem depois da Katica e da Csilla nas fontes da página: o texto fica na fonte da época e só o que ela não tem sai na Noto (com as faixas de cada fatia, um "1" seguido do FE0F e do 20E3 vira o emoji do teclado, e o "1" sozinho fica na Katica). Os nomes vêm do CLDR, pelo emojibase-data: `python3 -I ferramentas/emojis.py PASTA_DA_FONTE PASTA_DO_EMOJIBASE` refaz as fatias, as regras e a lista (o modo de baixar a fonte está no próprio roteiro).
- Os calendários da internet (`calendarios.js`): o endereço pode ser secreto (o do Google Agenda dá acesso à agenda inteira), então ele fica só no `config.json`; o que a área de trabalho e o Claude veem passa por `semSegredos` (`main.js`), que tira o `url` e põe o `site`, e as mensagens de erro são as próprias (por código), nunca a do Chromium. A lista (`agenda.calendarios`) só muda pelas rotas `calendarios:*`, que conferem o endereço; o `config:definir` da área de trabalho a ignora. O download é pelo `net.request` (o `net.fetch` não diz para onde o servidor redirecionou) numa sessão só na memória, sem cookies. Na área de trabalho, os eventos deles levam `_fonte` (o id do calendário), as repetições de cada calendário são abertas à parte (`ocorrenciasDe` em `agenda.js`) e os horários com TZID vêm para a hora daqui (`lerIcs(texto, { fusos: true })`; a Agenda do disco continua como foi escrita).
- No modo sistema, a janela do Retro Computer cobre a tela sem a tela cheia (`lugarNaTela` e `cobrirATela` em `main.js`): a tela principal inteira e um ponto a mais na largura, para o lado sem outra tela. No Openbox, uma janela em tela cheia com o foco (ou sem moldura e do tamanho exato do monitor) sobe para a camada da tela cheia, por cima até das janelas "sempre visíveis": o vídeo em janela flutuante sumia ao clicar na área de trabalho. Só a largura muda, para as margens das barras (medidas na página) continuarem certas; e o Chromium não deixa uma janela fora da tela cheia com o tamanho exato da tela. A tela cheia fica só para a tela de bloqueio (`bloqueio:naFrente`: ela precisa ficar por cima de tudo, também da janela flutuante do Navegador, que é do Retro Computer e não sai da frente com as do Linux) e para a de uma página (um vídeo). Sem a tela cheia, o Alt e arrastar do Openbox move a janela (a dica do Motif que tiraria o "mover" não serve: o `xprop` só a grava com o tipo CARDINAL, e o Openbox pede o tipo próprio dela), e ela volta sozinha ao lugar (os eventos `move` e `resize`). Confira com o roteiro `flutuante`. O Openbox é uma dependência do `.deb` (não só recomendação: o instalador do Mint deixava as recomendações de fora), e o `sessao.sh` espera ele ficar pronto antes de abrir o Retro Computer. Ao mexer na lista `depends` do `package.json`, mantenha as dependências padrão do electron-builder (`getDefaultDepends` em `FpmTarget.js`): a lista troca as dele inteiras.
- A Nuvem (`nuvem.js`) roda o rclone sem modificação, com o `rclone.conf` dela (`--config`, na pasta de dados, com a pasta 0700), nunca o do computador; o login é o `rclone config create … --non-interactive` com o `--state` e o `--result`, e o endereço da autorização (o `127.0.0.1:53682` que o rclone escreve) fica no processo principal: a área de trabalho só pede "abrir o navegador de novo" (`nuvem:abrirLogin`). As contas montam pelo FUSE com `--vfs-cache-mode off`: com a cópia guardada, desconectar logo depois de levar um arquivo perdia o envio. Uma conta é uma unidade (`nuvem:<id>`, `Unidades`): a mesma regra dos pendrives vale nela (trazer e levar cópias, nunca apagar nem gravar por cima). As montagens saem no fim (`encerrar`, também na troca de usuário e no desligar), e o `config:definir` da área de trabalho ignora `nuvem`.
- As caixas (`dialogo: true`) ficam umas sobre as outras na ordem em que abriram (`empilharDialogos` em `janelas.js`), cada uma com o fundo que bloqueia na mesma camada: a caixa aberta de dentro de outra fica sempre por cima. Ao fechar uma caixa, o foco vai para outra caixa aberta ou para a última janela usada (`recentes`), não para a última criada.
- O corretor ortográfico (`ortografia.js`): o Chromium procura os dicionários em `<dados do usuário>/Dictionaries`, com o nome que a versão dele pede (`pt-BR-3-0.bdic`…; ao subir o Electron, confira se o nome mudou e troque o arquivo pelo do repositório do Chromium). Eles são copiados no começo do `main.js`, logo depois de escolher a pasta do usuário e antes de qualquer sessão (com a sessão já criada, o Chromium tenta baixá-los), e o endereço de baixar fica num domínio `.invalid`. No Mac, o corretor é o do sistema, e os idiomas não se escolhem. O menu do botão direito de um campo vem do `context-menu` do Electron (só nos campos editáveis, com a palavra errada e as sugestões) para o `campos.js`, que o desenha no estilo da época; a troca e o dicionário do usuário passam pelo processo principal (`ortografia:trocar`, `ortografia:adicionar`), que confere a palavra. Os `input` do `h()` começam sem o corretor (os nomes, as buscas, os números); os campos de texto livre (o Bloco de notas, as notas, a descrição da Agenda) o ligam.
- As fontes de pontos (`ferramentas/fonte-serenity.py`) têm um contorno por mancha de pontos acesos (e um por buraco), não um quadrado por ponto: com os quadrados, o "hinting" leve do Linux (o padrão do Linux Mint) encaixava cada um na grade da tela por conta própria, e os tamanhos de pixel quebrados (1,25 ×, 1,5 ×, 2,5 ×…) abriam frestas brancas dentro das letras. Confira com o roteiro `letras` e o `FONTCONFIG_FILE` de um `fonts.conf` com `hintslight` (sem ele, o contêiner desenha sem "hinting" e não mostra o defeito).
- O Leitor de PDF (`leitorpdf.js`) desenha as páginas pelo pdf.js e as marcas por cima, como elementos da página: as anotações que ele sabe mudar (Highlight e Text) saem do desenho do pdf.js (`annotationStorage.setValue(id, { noView: true })` com o `AnnotationMode.ENABLE_STORAGE`), para não aparecerem duas vezes; o id delas é o da referência ("12R", "12R3"). O pdf.js 6 não tem `convertToViewportRectangle`: converta os cantos um a um. Quem grava é o processo principal (`pdf:marcar`, no processo de trabalho), que confere tudo o que vem da tela (`limparMarcas`: as cores de uma lista, os números, o tamanho dos textos, os ids) e só tira as anotações daqueles dois tipos (e o Popup delas); sem o `page.node.normalize()` do pdf-lib, que embrulharia o conteúdo da página em q/Q.
- A barra de tarefas e os programas do Linux (modo sistema): o Openbox não deixa um programa maximizado cobrir a faixa das margens do `rc.xml`. A sessão copia o `rc.xml` para uma pasta do usuário (`RETRO_OPENBOX_RC`), e a área de trabalho manda a altura da barra em pontos da tela (`faixasDasBarras` em `janelas-nativas.js`, com o `devicePixelRatio`) sempre que ela muda (a data, os pixels, o tema Mac com a barra no alto); o processo principal reescreve as margens e roda `openbox --reconfigure` (`margens` em `janelas-linux.js`). Para medir uma janela do X, use o `xwininfo`: o `xdotool getwindowgeometry` conta a moldura duas vezes. A moldura também segue o tamanho dos pixels: com as margens vem o `escala` (o `devicePixelRatio`), e o processo principal grava um tema numa pasta ao lado da cópia do rc.xml (`temaDoTamanho`: o themerc do tema "Retro" do pacote com as medidas do tamanho, `medidasDoTema`, e os desenhos dos botões do Retro Computer em .xbm, `GLIFOS`, num fator inteiro) e põe no rc.xml o caminho completo dele, que o Openbox aceita, e as fontes do tamanho (`trocarTema`; 9 pontos no tamanho 1 dão a barra de 18 pontos das janelas do Retro Computer). Um botão novo no `titleLayout` precisa do desenho dele em `GLIFOS`.
- Os cantos magnéticos das janelas do Linux (`cantos-linux.js`, só no modo sistema): o `xev -root -event substructure` (pelo `stdbuf -oL`, senão a saída fica presa) avisa cada movimento das molduras; um movimento sem mudar o tamanho, com o botão apertado, é um arrasto. O botão vem do `xinput query-state` de cada aparelho de apontar (o mouse, o touchpad, o de teste do `xdotool`): o ponteiro principal não responde. Não use o `xinput test-xi2 --root`, que também passaria as teclas. No meio do arrasto, o Openbox desfaz qualquer mudança de tamanho no movimento seguinte: a volta ao tamanho de antes (`voltarDoEncaixe`) é ao soltar. Ficam de fora as janelas sempre visíveis, as caixas e as de tamanho fixo (`encaixavel`). Confira com o roteiro `cantosLinux`.
- O bloqueio no modo sistema (`bloqueio.js`): sem a senha do Retro Computer, a de entrada do Linux bloqueia só com a conta com senha (`passwd -S` dá "P"; "NP" e "L", não), conferida pelo `unix_chkpwd`. A suspensão é segurada pela trava "delay" do logind (`TravaDoSono`, o `systemd-inhibit` rodando um `cat`, que termina com o Retro Computer) até a tela de bloqueio avisar que apareceu (`bloqueio:pronto`, dois quadros depois) ou por 2 segundos; a tampa é lida em `/proc/acpi/button/lid/*/state`. A configuração não guarda o `naProtecao` por padrão (a migração 5 tirou o falso que o padrão gravava): sem ele, a proteção de tela pede a senha só no modo sistema. Como o `config.json` grava o objeto inteiro, mudar um padrão pede uma migração em `migrar()`.
- O chaveiro do Linux no modo sistema (`chaveiro.js`): com o `password-store` em `gnome-libsecret` e o chaveiro trancado (a entrada direta, sem senha), qualquer chamada do `safeStorage` (até o `isEncryptionAvailable`, que o `config:obter` faz) abre a caixa do gcr e para o processo principal até ela fechar: a janela não se redesenha, e arrastar a caixa deixa rastros. Por isso, o estado é lido na abertura pela propriedade `Locked` do `/org/freedesktop/secrets/aliases/default` (o `gdbus` ou o `busctl`, que não pedem nada; o objeto que não existe é o "sem chaveiro"), e, trancado, o `Config` não toca no cofre (`trancado`). A senha vai para o socket de controle do gnome-keyring (`$XDG_RUNTIME_DIR/keyring/control`, o protocolo da pam_gnome_keyring: um byte zero e o pedido de abrir, op 1; a resposta 0 é aberto, 1 é senha errada), só se o socket e a pasta forem do usuário; sem chaveiro ainda, ele seria criado com qualquer senha, então só com a de entrada (`conferirLinux`). O `gnome-keyring-daemon --unlock` não serve: com um daemon já rodando, ele não abre o que roda. Um uso novo do `safeStorage` passa pelo `Config` (ou confere o `chaveiroTrancado` antes).
- Os cursores do `estilo.css` são escritos como `cursor: var(--cur-default, default)` (o `--cur-…` é o cursor grande da Acessibilidade); um cursor novo segue o mesmo formato.
